User guide

ClassAct

A studio for NVIDIA Object-Oriented Agents. An agent is a Python class. Methods are capabilities. A method whose body is … is filled in at runtime by an LLM.

Default model: open Nemotron 3.5 Lightning on hosted NIM. No GPU on your desk.

Sixty seconds

  1. Inspect — select ClassifierAgent. The card shows … classify (Predict).
  2. Click that method row (or press R) and type: Great product, but shipping was slow.
  3. Run agent or ⌘↵. The reply stays on Run; spans stream on the right.
  4. + New agent on Inspect opens Build on a blank MyAgent. Press +, then Generate class.
  5. The file lands in workspace/ and shows up in the Inspect rail.

Inspect and Build work without a key. Run needs NVIDIA_API_KEY.

Architecture

Browser

   ▼
ClassAct  FastAPI
   ├─ Inspect   catalog/ + workspace/

   ├─ Build     class graph → Python file
   ├─ NOOA      class = agent, … = LLM
   └─ LiteLLM ── HTTPS ──► NIM  Lightning

ClassAct does not fork NOOA. It reflects classes, runs them with your NIM key, and writes new modules into workspace/.

What NOOA is

A harness, not a new model. Same ingredients as other agents (LLM, tools, loop, state). The new abstraction is where they live: one Python class instead of prompt + tool JSON + graph.

Usual stackNOOA
System promptClass / method docstrings
Tool schemasMethods on self
Workflow graphOrdinary Python
agent.invoke(text)await agent.triage(message, order_id)

LLM text can still be wrong or invented. Python tool returns are deterministic. Catalog orders are demo data, not a live store.

Kind and strategy

These are per method, not for the whole class. A class can mix all three.

Meaning
Kind: PythonYou write the body. A tool. No model.
Kind: AgenticBody is …. The LLM implements it.
Strategy: PredictTyped answer, no tools (e.g. classify).
Strategy: CodeActModel writes Python and can call self.get_order(...) (e.g. triage).

get_order is a method. Its input is order_id. Strategy is hidden when Kind is Python. Kind and strategy set that method on the generated class, not a separate workflow file.

Quick start

Python 3.12 or 3.13 required. Inspect and Build work with no key.

python3 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env   # NVIDIA_API_KEY from build.nvidia.com
./run.sh
# → http://127.0.0.1:7877
# → http://127.0.0.1:7877/docs
NOOA_MODEL=nvidia_nim/nvidia/nemotron-3.5-lightning-30b-a3b
NIM_MODEL_ID=nvidia/nemotron-3.5-lightning-30b-a3b

Never commit .env.

Inspect

The rail lists agents from catalog/ (shipped) and workspace/ (generated).

+ New agent opens Build on a blank MyAgent — no methods. Press + on the graph to add a capability. Workspace agents have × on the rail and Delete on the agent pane. Catalog agents cannot be deleted here.

  • Fields — public annotated state
  • Methods — … is agentic (LLM); def is ordinary Python
  • Source — the file on disk

Click a method row to jump to Run. Open in Build copies the current class onto the canvas (not blank).

Run

A prompt console. Submitting does not leave this tab.

You pick the method. The query does not auto-select get_order vs triage. The dropdown is the entry point. CodeAct may call other methods inside that run. There is no chain to draw in the GUI.

For “I want to return my headphones”, set Method to triage, not get_order. get_order expects ORD-1001. Changing the dropdown does not re-run the last reply.

  1. Pick agent, method, and model. Default method is the first agentic one.
  2. Type into the large box — that is text / message / prompt.
  3. Extra arguments (order_id, …) sit under the prompt.
  4. Use a Try chip, or press ⌘↵ / Ctrl+Enter.

Reply is a readable card; JSON sits underneath. Live trace streams spans on the right. Python tools return demo data; Predict / CodeAct text can be invented.

AgentMethodWhat to type
ClassifierAgent classify A customer review. Returns a typed FeedbackAnalysis.
SupportAgent triage A support message plus order_id (ORD-1001, ORD-2044, ORD-3302).

Watch

Each box is an OpenTelemetry span. Nesting follows the Python call tree:

  • method.<name> — agent method
  • generation — Predict or CodeAct loop
  • litellm.acompletion — NIM call
  • code_execution — a CodeAct Python cell

The same tree is mirrored on Run while a call is in flight.

Build

A live object graph. The class in the center is a label, not an editor.

  • Class name / Role — fields above the graph.
  • Templates — Headline, Classifier, Support, Blank.
  • Method nodes — selected node is high-contrast green; others dim. Click to inspect; drag to rearrange. + adds a capability.
  • Inspector — Agentic (…) vs Python tool; Predict vs CodeAct; args; docstring. Python tools have a body editor; agentic methods stay ….
  • Live Python updates as you type. Generate class writes workspace/.

+ New agent loads Blank. Open in Build loads the agent you were inspecting. Class names must be PascalCase. The graph is the class, not a flowchart.

From studio to production

Test here, then copy the class and the same call. ClassAct is the studio; NOOA is what you ship:

python examples/take_home.py --dry-run
python examples/take_home.py "Great product, but shipping was slow."

agent = ClassifierAgent(llm=llm)
result = await agent.classify(text)

Inspect Source is the file to take. Add your HTTP, auth, database, and run CodeAct inside OpenShell or a container. Construct a new instance per request so state does not leak. ClassAct is not the production server.

Models

The Run dropdown talks to hosted NIM. Default is Lightning. Nano and Super are also listed. Override with NOOA_MODEL in .env. No local GPU.

Safety

NOOA can execute model-generated Python. + New agent is blank — add Agentic methods as Predict unless you opt into CodeAct. Shipped CodeAct tools are in-memory only. Framework checks are not a sandbox: use a container, a VM, or NVIDIA OpenShell.
